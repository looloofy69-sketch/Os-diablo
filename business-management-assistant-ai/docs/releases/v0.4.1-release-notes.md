# business-management-assistant-ai v0.4.1 — Release Candidate (refreshed)

**Status:** Review/staging candidate. Source is integrated in the OS Diablo repository under `business-management-assistant-ai/` on branch `integrate/v0.4.1-app-source`; it is not tagged, merged, deployed, or production-verified.

## Changes included

### Performance
- Bounded top-k task ranking uses a heap for small result limits rather than sorting the complete scored set.
- Briefing queries select only the task fields needed for exact summaries and ranking.
- Concurrent initial model discovery coalesces refresh requests.
- The benchmark warms both ranking implementations, alternates measurement order, records raw samples, and fails if IDs or reasons diverge.

### Logic validation and external-action safety
- Model/provider endpoint configuration validates URL structure, credentials-in-URL, key-source exclusivity, model and role types, finite numeric ranges, booleans, and duplicate endpoint names before network calls.
- Model ranking now accepts a measured score only when it is a JSON object with a finite accuracy in [0, 1] and an explicit integer `graded` count of at least ten. **Legacy numeric scores and accuracy-only entries without a graded count are ignored. Re-run `python scripts/evaluate_models.py` to regenerate trustworthy measured scores.**
- Evaluation datasets validate JSONL structure and unique IDs before provider requests; evaluation results are atomically written and upper-bound provider call counts are reported.
- Connector outcomes include an explicit `outcome_unknown` boolean, independent of `retryable`. Approval execution persists this typed field rather than parsing error text.
- All non-2xx HTTP responses for generic connector actions are outcome-unknown and not auto-retryable. Network failures known to happen before delivery can be retryable; ambiguous transport and SMTP send-stage failures are marked unknown.
- HTTP redirects are disabled for signed webhook action POSTs and model API requests.
- Webhook configuration rejects whitespace/control characters, embedded credentials, malformed/empty/out-of-range ports, query strings/fragments, invalid field types, duplicate normalized prefixes, and invalid timeouts.
- Release packaging excludes caches, databases, local environment files, model payloads, evaluation outputs, common key/certificate files, Terraform state, and credential/private-key directories, case-insensitively.

### Synthetic benchmark

50,000 generated tasks, top five, two warm-ups and five alternating-order measurements, on Python 3.13.5 (Linux-6.18.55-x86_64-with-glibc2.41): optimized median **0.037587 s**, reference full-sort median **0.093045 s**, observed speedup **2.475×**, identical top task IDs and reasons. Raw timings are included in `BENCHMARK-v0.4.1.json`.

This is a synthetic CPU microbenchmark, not an end-to-end API, database or provider latency guarantee.

## Remaining release gates

- The full `pytest -q` cannot collect API tests because `sqlmodel` is missing in this sandbox.
- Ruff and Docker are unavailable; package-index DNS resolution prevented installing missing dependencies.
- The new approval-level typed-outcome regression test is present in the API suite but was not executed because the API suite fails during collection.
- PostgreSQL integration/migration-upgrade tests, Docker build/start, live model-provider evaluation, SMTP via Mailpit, Slack delivery, signed-webhook receiver behavior, browser E2E, and realistic database/API load remain **unverified**.

Blocked checks are not passes. Do not tag/deploy as production-ready until mandatory release checks pass on the exact source commit.
