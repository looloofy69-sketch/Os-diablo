## Performance changes

- Task ranking uses bounded top-k selection with `heapq.nsmallest`, keeping the score and tie-ordering keys while reducing selection work from O(n log n) to O(n log k) for a small result limit.
- Briefing selects only six task fields needed for counts, overdue/blocked summaries and ranking instead of materializing full Task rows.
- Concurrent first model-discovery requests share one in-flight refresh; endpoint probes remain bounded.
- Evaluation JSONL validates schema and unique row IDs before provider calls. Model count and per-model example count are separate; the evaluator prints the upper-bound call estimate and atomically writes results/scores.
- Only finite accuracy in [0, 1] with at least ten graded examples can update measured model-ranking scores.

## Additional correctness improvement found during the continued review

The review found that approval execution inferred `outcome_unknown` by searching human-readable connector error text. A timeout whose message did not include the word “unknown” could therefore be persisted incorrectly.

This candidate adds an explicit `outcome_unknown` boolean to connector results, independent of `retryable`, and approval persistence uses the typed field rather than parsing error detail text.

- Every non-2xx HTTP response is non-retryable and outcome-unknown because a generic receiver response cannot prove that no side effect occurred before the error.
- DNS failure or connection refusal before an HTTP connection can be safe to retry; ambiguous transport failures are explicitly unknown.
- SMTP failures after sending may have started explicitly set `outcome_unknown=True`.
- Connector documentation now matches the behavior.
- HTTP model requests and signed webhook POSTs do not automatically follow redirects. HTTP-error response streams are closed after classification.
- Evaluation scoring preserves duplicate tool-call counts rather than collapsing proposals into a set.
