## Performance changes

- Task ranking uses bounded top-k selection via `heapq.nsmallest`, preserving score and tie ordering while reducing selection work to O(n log k) for small k and using O(k) result storage.
- Briefing queries select only six fields needed by task summaries/ranking rather than materializing complete task records.
- Concurrent first model-discovery requests share one in-flight refresh.
- Evaluation controls validate JSONL structure and unique row IDs, separate model count from examples/model, estimate provider calls, and write results/scores atomically.
- The benchmark warms both paths, alternates timing order, records raw samples, and checks task IDs/reasons for every measurement.

## Logic and safety fixes

### Model ranking evidence
Only scores with finite accuracy in [0, 1] and an explicit integer `graded >= 10` are trusted. Legacy numeric scores, accuracy-only entries, boolean/float graded counts, undersampled entries and non-finite/out-of-range values are ignored. Re-run `python scripts/evaluate_models.py` to regenerate ranking evidence after upgrading; heuristic ranking is used where no measured score is accepted.

### Typed connector outcomes
The connector contract now carries an explicit `outcome_unknown` boolean separate from `retryable`. Approval execution persists this typed field rather than parsing human-readable error text. This avoids misclassification when a timeout or transport failure message uses different wording.

- Generic HTTP connector non-2xx responses are marked outcome-unknown and are not auto-retried, because the receiver response cannot prove it performed no side effect.
- Connection failures known to occur before delivery can be retryable; ambiguous transport failures are outcome-unknown.
- SMTP send-stage disconnects/timeouts are explicitly outcome-unknown.
- A new API regression test covers the distinction between typed outcome state and misleading detail text. It is present but could not be executed here because API test collection is blocked by the missing `sqlmodel` dependency.

### Outbound configuration and packaging
- Webhook URL checks reject whitespace/control characters, embedded credentials, malformed/empty/out-of-range ports, query strings and fragments.
- Webhook route parser rejects non-string fields, unsafe action-family prefixes, duplicate normalized prefixes, insufficient/whitespace-padded secrets and malformed URLs.
- Slack and signed-webhook constructors reject boolean, non-finite, nonpositive or excessive timeout values.
- Model API requests and signed action POSTs do not follow redirects.
- Release packaging excludes runtime caches, local databases, local environment files, model payloads, generated evaluation outputs, common key/certificate files, Terraform state and credential/private-key directories, case-insensitively.
