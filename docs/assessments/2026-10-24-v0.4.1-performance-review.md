## Changes included in the candidate

### Performance changes
- Replaced full sorting for small task-ranking results with bounded top-k selection via `heapq.nsmallest`, preserving score and tie-ordering logic.
- Narrowed briefing reads to six task columns rather than materializing full ORM task records.
- Coalesced concurrent initial model discovery so only one refresh is in flight while endpoint probes remain bounded.
- Added a source ZIP packager that excludes caches, local databases, environment secrets, model payloads and generated evaluation outputs.
- Added a microbenchmark that compares the optimized implementation against the previous full-sort reference and fails on output mismatch.

### Logic validation and external-action safety
- Validated endpoint names/providers/URLs/credentials/model lists/roles/numeric ranges/booleans/duplicate names before discovery and calls.
- Validated direct model-pool constructor settings rather than trusting only the environment parser.
- Rejected malformed, non-finite, out-of-range or undersampled model scores as ranking evidence.
- Added schema checks for evaluation JSONL, unique row IDs, duplicate-tool-sensitive scoring and a minimum of ten graded examples before measured score promotion.
- Separated model-count and per-model-example limits, gave an estimated call count, and wrote evaluation outputs atomically.
- Corrected ISO date-only parsing to the end of the UTC day.
- Classified ambiguous connector responses as unknown rather than asserting the receiver definitely did nothing.
- Disabled automatic HTTP redirect following for signed webhook POSTs and model API requests to avoid forwarding signatures, credentials, payloads or prompts to an unvalidated destination.
- Added a regression test for model-payload exclusion from release packaging.

## Validation evidence

- Unit tests: **150 passed** under both `unittest` and `pytest`; pytest also reports **16 passing subtests**.
- Python compilation, release-script shell syntax, and local Compose/CI YAML parsing: passed.
- The final ZIP was extracted into a clean directory and the packaged unit suite reran: **150 passed, 16 subtests passed**.
- Release ZIP packaging repeated with the same SHA-256; archive CRC, required files, exclusion rules and manifest checksum verification passed.
- Synthetic CPU benchmark: 50,000 generated tasks, top five, median of five runs. The packaging-pass run measured **0.038082 s** top-k vs **0.098329 s** full sort (**2.582×**). Five subsequent runs on the exact same source measured **2.348×, 3.032×, 2.517×, 2.520×, and 3.044×**; all produced identical top task IDs. Runtime elapsed times vary, so these are synthetic CPU observations, not service-level performance guarantees.

## Evidence boundary and remaining release gates

This is a source-level candidate and a synthetic benchmark, not an end-to-end load-test result. The local environment lacked `sqlmodel`, Ruff and Docker, and package-index connectivity was unavailable. The following remain unverified:
- Full API/integration and dependency-backed concurrency suites.
- PostgreSQL integration and migration/upgrade tests.
- Ruff.
- Docker image build and startup.
- Live model-provider evaluation.
- SMTP delivery via Mailpit, Slack delivery and signed-webhook receiver contract behavior.
- Browser E2E tests, database throughput and production load/latency.

The ZIP is a deliverable for review and controlled staging validation, not proof of a production-ready release. The changes have not been integrated into a canonical application-source repository or deployed.
