## Candidate changes represented

- Top-k task ranking uses a heap for small result limits while preserving reference ordering.
- Briefing reads select only the fields required for task summaries.
- Concurrent first model-discovery refreshes are coalesced.
- Endpoint, connector timeout, webhook route, score-evidence and packaging validations are strengthened.
- Connector results carry a typed `outcome_unknown` field; approval persistence does not infer delivery certainty from free-form error text.
- Ambiguous webhook/SMTP failures are not automatically retried; HTTP redirects are disabled for model and action POSTs.
- Evaluation data is validated before provider calls, and under-sampled scores do not influence model ranking.
- The container has a writable SQLite path for sandbox mode and can initialize against PostgreSQL through Compose/migrations.

## Performance evidence

The synthetic 50,000-task, top-five ranking benchmark recorded a median of 0.037587 seconds for top-k versus 0.093045 seconds for full sorting (2.475× in that run). Task ordering matched. This is a CPU microbenchmark, not an end-to-end database or API throughput result.
